# Checkpoints, practice and reference provenance

`checkpoints.json` is the machine-readable catalog. `scripts/verify_setup.py` verifies every listed bundled file and the framework's locked external files before a reviewer starts the app. Startup independently enforces the canonical framework lock and Ava's converted-asset provenance. Neither verification process trains a model or changes expected identities.

## Browser Lab revision versus working-tree snapshot

The recorded Browser Lab revision, `b4df0f69ea99ddb31ec40c9006a933e90c132bc7`, identifies the checkout's base commit. **That commit does not contain the audited current application files or the trained Ava JSON.** Their individual SHA-256 records in `data/ava/provenance.json` and `docs/device-port-provenance.json` identify the actual working-tree snapshot used for the port.

Do not claim that checking out that commit alone reproduces the browser source snapshot. Runtime, normal tests and installation are independent of Browser Lab because the converted weights, practice and reference fixtures are supplied here. Optional regeneration requires the matching audited snapshot, selected using `BROWSER_LAB_ROOT`. Keep any regenerated change reviewable; it is not a reason to overwrite a user's learned model.

## Practice and retained fixtures

- `data/chatbot/practice.json`: eight-example sets originally generated by the canonical train-split generator, development seed 53212, simple difficulty, with source interpreter-checked labels. These are practice examples, not a protected test set.
- `data/devices/practice.json`: the Python port of `device-location-messages-v1`; Delivered updates, Missing updates and Mixed sequences. Tests compare the source encoding and independently verify all 24 labels with the pinned canonical interpreter. That interpreter does not choose runtime predictions.
- `tests/fixtures/device-language.json`: retained canonical Python logits/predictions and label records, with interpreter identity.
- `tests/fixtures/ava-browser.json.gz`: compressed executable browser reference cases, world observations, labels, histories, logits, gradients and a real optimizer update. No browser runtime is loaded during normal Python inference or training.

All bundled file hashes, including duplicated starter text files and metadata, are in `checkpoints.json`. The small converted Ava payload is intentionally included in Git; it is not an ignored user checkpoint. Git LFS is not required for these supplied assets. `.gitattributes` marks tensor/fixture binaries so line-ending conversion cannot damage them.

## Saved model identities and sharing boundaries

The learned-state hash identifies named tensor values. It is distinct from a checkpoint-file hash, which also covers optimizer, drafts and simulation metadata and can change after a save without changing learned weights. Model and Playground display the selected learned identity; prior outputs become stale when training changes it.

`state/`, `artifacts/`, virtual environments and local `.env` files are ignored. They must not be included in a shareable source snapshot. The source catalog deliberately contains no user-trained models, browser storage, absolute developer paths, API credentials or fabricated training results.

Code and supplied materials retain `LICENSE` and upstream attribution in `NOTICE`. No remote repository, release, hosted site or deployment was created during this preparation.
